# 开发决策与项目复盘

## 2026-09-16：公开数据评测与融合调参

**用户提出**：主动寻找 GraphRAG 和其他项目的相关数据集开展调优；交付只能通过 PR，并给出手动及面试验收内容。

**Agent 建议并实现**：采用 HotpotQA 支持事实作为文档级相关性标签，建立共享融合评分、调参/测试分组、冻结配置和消融评测。用户尚未亲自验收，不将实现表述为用户亲手完成。

### 主流程

现有服务：文档索引 → 向量/关键词/图谱召回 → WeightedRanker 融合 → 上下文与答案生成。新增实验：固定公开数据与模型 → 全上下文语料 → 两路候选与标题图 → 调参冻结 → 独立题目测试 → HTML/JSON 证据。两者共用融合函数，但基础检索服务与图构建不同。

### 本轮主要难点与解决证据

难点是如何判断“图有帮助”，而不是凭演示回答感受判断。原始分数尺度不同，改变向量/关键词权重也会影响结果。

实现了可选 RRF 和原加权公式，通过固定调参集选参；首轮测试后发现图增强和混合方案选出的权重不同，补充保持权重一致、只关图增益的消融。原冻结时间及配置保留，未按测试成绩重选。240 题同参数消融得到 Recall@5 76.67% → 83.54%，也保留 1 题退化。详见 evaluation/evidence。

这只能称为本轮有记录的主要技术困难，不能断言它是用户整个项目历史中“最大的困难”，也不能代写用户亲历。

### 取舍与状态

- HotpotQA 有明确支持文档，适合自动算召回率。未实际比较其他数据集优劣；选择理由是任务匹配与可追溯标签。
- 采用本地标题提及图：无付费模型、可复现、不用标签建边；代价是不能验证企业实体抽取与复杂关系推理。
- 加权融合 vs RRF：本轮网格已实际比较，调参最终选加权；结果只适用于当前模型/英文语料/网格，不能说加权普遍更好。
- 线上默认参数保持原值；换中文数据或生产索引后必须重新验证。数据集扩大时也需重新划分未看过的测试题。
- 模型固定版本，未微调。随机种子、阈值、依赖、源码哈希和结果见 README 与 evidence。实验阶段工作树 dirty=true 是真实记录，不伪装成已提交版本实验。
